## 1. 走过的四个阶段（时间线）

### 阶段一：P1 无铜片（2026-07-21 ~ 07-24）——搭台 + 选型

**做了什么：**
- 搭出第一版：ESP32 + TEC + 散热器 + 3 颗 DS18B20 + OLED + 网页仪表板 + CSV 导出
- **TEC 选型对比**：12703（3A/36W）vs 12706（6A/72W），同散热条件各测制冷/加热
- **降压试验**：12703 降到 8.5V 看能不能省电还够用
- CSV 导出与自动调节功能冒烟测试、一次 63 分钟制冷长测

**结果：**

| 指标 | 12706 | 12703 | 结论 |
|---|---|---|---|
| 制冷降温 Δ | −4.2°C | −4.6°C | **12703 略優（速率 0.448 vs 0.414 °C/min）** |
| 加热升温 Δ | +6.7°C（1.31°C/min） | +7.0°C（1.48°C/min） | 12703 略快 |
| 功耗 | ~72W | 36W | **12703 功耗仅一半** |

- **选定 TEC1-12703**：制冷略優、加热更快、散热压力小一半。
- **8.5V 降压否决**：制冷只降 −3.62°C（比 12V 的 −4.6°C 明显差），省的电不抵损失。
- 63 分钟长测基线：出风口最低 24.07°C，巢穴稳在 24~26°C。
- 本阶段只能降 ~4.6°C —— 这就是后来加铜片、加密封箱、风扇降速的动因。

### 阶段二：P2 有铜片、无隔温板（2026-08-01）——关键突破 🎯

**做了什么：** 热端加 0.3mm 铜片改善导热；在 20×24×16cm 密封箱内、室温 24–25°C 下做整机实测；顺手试了冷端风扇不同转速。

**结果：**

| 配置 | 出风口最低 | 巢穴 |
|---|---|---|
| 风扇全速 100% | 18.6°C | — |
| **风扇 52%** | **14.87°C** ✅ 达论文 15°C | 22.19°C |

- **铜片是热端散热关键件**，ΔT 由 1.4°C 提升到 18.5°C。
- **反直觉发现：冷端风扇不是越快越好。** 全速时大量室温空气被送到冷端面前，TEC 的泵热能力全花在"冷却新进来的空气"上，冷端反而被拉高。降到 52% 后空气在鳍片里停留更久、换热更充分，出风口掉到 14.87°C。
- 这一条是全过程最有说服力的工程结论，演示和答辩都用它。

### 阶段三：诊断 + 铝均温板（2026-08-27 ~ 09-06）

**做了什么：** 手测温：热端 Th ≈ 28°C、冷面 Tc ≈ 5–6°C —— 说明 **TEC 本身没到极限，瓶颈在冷端换热面积（仅 16cm²）**。于是加 100×150×2mm 铝均温底板 + 导热硅脂，把冷量摊开。

**结果：** 室温 27–28°C 下**改善不明显**。判断：室温太高，把系统下限整体抬起来了，铝板的效果被掩盖。**决定不再继续堆温度优化**——温度已到工程甜点，继续投入对比赛得分没帮助。

### 阶段四：P3 有铜片 + 隔温板（2026-08-26 ~ 08-31）——收尾

**做了什么：** 加隔温板（减少箱内热桥），做整机长测。

| 数据 | 时长 | 风扇 | 出风口 | 巢穴 | 活动区 |
|---|---|---|---|---|---|
| 0826 | 56 分钟 | 100% | 16.87°C | 26.50°C | 20.38°C |
| 0831 其一 | 23 分钟 | 100% | 23.03°C | 探头掉线 | 18.69°C |
| 0831 其二 | 43 分钟 | 62% | 22.52°C | 探头掉线 | **16.76°C**（全程最低 16.75\*，全库最低活动区） |

> 0831 两次巢穴探头掉线，数据只有两通道可用；0826 巢穴列有 70.1°C 异常尖峰（出現于開機后 +7:33，須逐行剔除）。
> \* 表中 P3 数值均为**收尾值**；全程最低：0826 出風口 16.50 / 巢穴 21.20（风扇 0% 維持段）、0831 其一 出風 23.02、0831 其二 活動 16.75 / 出風 22.50。

### 2026-09-10：收尾锁版

- **温度优化冻结**：15°C 为工程甜点，不再追更低。
- **转向航天/生命保障创新点 + 工程迭代叙事**（评委看得见的东西）。
- 18 份实验 CSV 按三阶段归档重命名：`P1-无铜片` / `P2-有铜片无隔温板` / `P3-有铜片有隔温板`。

## 2. 遇到的问题与怎么解决的（工程思想）

| # | 遇到的问题 | 原因 | 怎么解决 | 结果 |
|---|---|---|---|---|
| 1 | 制冷时温度反而上升 | 固件喊"制冷"、硬件实际在制热：TEC 电源线与固件方向定义不一致 | 把 TEC 电源线**对调**接法 | 后续制冷正常（8/01 达 14.87°C）。答辩按"数据发现方向异常 → 对调验证"讲，不写具体日期 |
| 2 | 制冷只能降 4.6°C | 热端散热不足 + 冷端换热面积只有 16cm² | 热端加 0.3mm 铜片 | ΔT 由 1.4 → 18.5°C，出风口 18.6 → 14.9°C |
| 3 | 冷端风越大反而越热 | 全速风把室温空气持续压到冷端面前，冷量被"吹走" | 冷端风扇降到 50–52%（实测最优） | 出风口 14.87°C，达标 |
| 4 | 探头读到 0 / deviceCount=0 | `doScan()` 排在 WiFi 初始化之后，WiFi 中断抢了 OneWire 时隙 | 把 `doScan()` 提到 `WiFi.mode()` 之前 | 三探头稳定识别 |
| 5 | OneWire 接某脚会变砖 | D13 = GPIO12 是 strapping pin，4.7kΩ 上拉会让 ESP32 误判 flash 电压 | 改接 D12（GPIO4），并写进文档警告 | 避免烧板 |
| 6 | OLED 热插拔后不亮 | 启动时 I2C 地址已定，之后插上不再检测 | 每 5 秒轮询 + I2C 重扫 | 热插拔自动恢复 |
| 7 | 温度数据不可比 | 环境温度不同、起点不同 | 定"统一起点"协议：制冷前先加温/平衡到 **29–30°C** 再测降温 | 12703 vs 12706 可比（29.5 vs 29.1） |
| 8 | 断电后参数全丢 / WiFi 连不上 | EEPROM 未初始化时 SSID 读成 0xFF；且 wifiPass 地址与 wifiSSID 重叠 | 加 `0xAA` 有效标记 + 空值回退默认；地址 67 → 68 | 参数持久化正常 |
| 9 | 加热太快，超论文上限 | Peltier 焦耳热叠加泵热，加热天然比制冷快 3 倍 | 目前 1.31–1.48°C/min > 论文 0.7–1.0 上限；**需切 PI 控制 + 速率节流才能真正压住**（未做，锁版冻结） | 已记录为已知不足 #2 |
| 10 | 箱内会有冷凝水 | 冷端表面低于露点 | 网底架空；集水结构不做（2026-09-10 定） | 待验证 |
| 11 | 巢穴探头掉线（0831） | 接线/插头松动 | 演示前必须检查三探头在线 | 数据只两通道可用 |

**展示时的"问题→解决"叙事线（推荐 3 条）：**
1. 信号方向错 → 数据发现异常 → 对调验证（故障诊断）
2. 冷量被风带走 → 反直觉发现风扇降速更冷（参数优化，有数据）
3. 换热面积是瓶颈 → 加铜片/铝板（结构改进）

## 3. 现在这台机器有什么功能

### 已实现（可用）

| 功能 | 说明 |
|---|---|
| 三路温度监控 | 3× DS18B20 分角色：**巢穴**（控温依据）/ **活动区**（环境参考）/ **出风口**（过热保护） |
| 自动温控 | bang-bang：目标温度 ± 死区，超出即满功率制冷或加热 |
| 多重安全保护 | 出风口 ≥ ventMax 立刻断电；巢穴超出安全区间关 TEC；传感器连续 3 次异常（NAN）紧急断电；断电后风扇延迟 10 秒吹散余热 |
| 网页仪表板 | 手机/电脑浏览器打开即用：实时温度、状态、趋势图、目标温度/死区/安全阈值滑条、风扇手动控制 |
| OLED 屏 | 板载实时显示，热插拔可恢复 |
| CSV 导出 | 一键导出实验数据（时间/巢穴/活动区/出风口/风扇/状态） |
| WiFi 双模式 | 纯热点（默认）或连接指定 WiFi 做备援 |
| 行为相机 | 独立的 ESP32-S3 AI Camera 模块，双端口（串流 80 / 控制 81），网页里内嵌画面 |
| 单元测试 | 37/37 PASSED（`pio test -e native`） |

### 待装机（货到就装，6 件）

| 项目 | 接法/位置 | 作用 |
|---|---|---|
| BME688 | I2C，与 OLED 并线（GPIO21/22） | 箱内温湿度/气压/气体相对值（**注意：eCO₂ 是估算值，不是真 CO₂ ppm**） |
| LED 灯带（12V 4000K，30–40cm） | GPIO27 → IRLZ44N MOSFET 驱动 | 光周期/昼夜模拟 |
| HEPA + 活性炭棉 | 塞在冷端风扇进风侧（脏空气 → HEPA → 炭 → 风扇 → 冷端） | 空气净化 |

| 304 不锈钢网（8 目） | 双层箱底 | 排泄物下漏、动物不接触积水 |
| 相机进箱 | 箱内（睡眠模式补光 + 自热除雾） | 行为观测定点记录 |

### 明确砍掉（本阶段不做）

SCD40（真 CO₂）、MQ-137（氨传感，半定量、数据写不进论文）、INA219（功耗可用额定值估）、蜂鸣器、BSEC/AI Studio 软件栈、进一步的温度优化。

## 5. 已知不足（诚实清单，别踩）

1. **自动模式风扇写死全速**：代码里制冷分支是 `setFan(255)`，而实测最优是 52%。**自动跑达不到 14.87°C，必须手动设 52%**（`LIMITATIONS.md` #34）。
2. **加热速率超标**：1.31–1.48°C/min > 论文 0.7–1.0 上限，要 PI 控制 + 速率节流才能压住，目前未做（#2）。
3. **EEPROM 浮点参数没有越界校验**：flash 万一损坏会读出畸形目标温度。概率低，演示前开机看一眼数值正常即可（#35）。
4. **安全阈值没有互相校验**（safeMin 可以设得比 safeMax 大），**探头整组掉线不会自动断电**。别乱改阈值，演示前查接线（#36）。
5. **箱体保温不够**：出风口 14.87°C 但巢穴 ~22°C，论文要的 15°C 是**箱内环境**，靠隔温板/保温继续改善。
6. **BME688 没有真 CO₂**：只能给 VOC/估算法，写论文时只能当"环境相对值"，要真 ppm 得上 NDIR（SCD40）。
