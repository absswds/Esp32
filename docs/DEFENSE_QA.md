## 0. 先處理的風險（答辯前改）

1. **作品簡介和實物不一致**：`docs/reports/作品簡介.docx` 還寫著 HEPA 濾芯、活性炭、吸附墊（最近一次提交已確認「最後沒裝」）。評委若拿簡介對照實物問，會很難堪。答辯口徑：「簡介裡的廢物導流是**設計構想**，樣機只實裝了定向氣流 + 雙層不鏽鋼網。」
2. **簡介寫「37 項測試通過」**，現在是 41 項（10-04 起）。報數字前統一。
3. **簡介說「五重安全保護」**，數的時候跟簡介（1 感測器連續無效停機、2 出風口過熱停機、3 巢穴超限關 TEC 留風扇、4 看門狗、5 斷電保存自動恢復）一致，別現場臨時數成別的數。
4. 簡介寫「出風口 14.87°C」，口頭統一說「約 15°C（14.9）」。
5. 手動模式沒有保護（README 已標），被問到安全時不要說「所有情況都有保護」，說「自動模式下有」。
6. **簡介裡其他和實物/數據對不上的說法**（簡介 10 月底已定稿改不了，統一口徑）：
   - 「熱端對接塔式熱管散熱器」→ 塔式散熱器早期試過，體積大、噪音大已棄用，現在是箱外鋁鰭片散熱器 + 銅片。
   - 鋁板「經對比後拆除」→ 沒有可用的對照數據（08-31 是手動模式且缺巢穴探頭），說「試過，效果說不清，拆了」。
   - 「風扇佔空比與製冷效果的關係曲線」→ 只有 100% / 50% / 52% 三個點，沒做檔位掃描。
   - 「確認 52% 時最低」「實現致冷（降溫至 15℃）」→ 只說「降速優於全速」「出風口到約 15°C，巢穴沒到」。
   - XPS「符合航天艙內無毒安全標準」→ 沒有依據，被問就說「這句說過頭了，我們沒做過相關檢測」。
   - 「具備可重複驗證性」「24 小時連續監測」→ C 組（14.87°C）只測過一次；最長連續實測約 63 分鐘。
   - LED「12L:12D」、Lixit 飲水嘴「經過太空驗證」、紋理內壁、封閉巢穴 → 燈帶只能手動調光，沒有定時；其餘以實物為準，**沒裝的一律說「設計構想」**。
7. **斷電恢復答辯前拔一次電試掉**（約 10 分鐘）：自動模式開著 → 拔 12 V 和 ESP32 供電 → 插回 → 看網頁是否自動回到運行、TEC 有沒有真的通電。試過才能說「驗證過」。
8. **有時間就用現機（有 XPS）手動 52% 跑 30–40 分鐘**：巢穴 22°C 是 P2（沒裝 XPS）測的，現在這台箱子從沒在 52% 下測過；跑一次既有「現在的數字」，也補上 XPS 同風速對照。

## 1. 必背：開場 + 一句話版本

**30 秒版：** 載人深空飛行會讓航天員肌肉萎縮、骨質流失。冬眠類動物低代謝時這些損失更小。脂尾袋鼩每天能自發蟄眠、體型小，適合做實驗動物。我們做的是**面向未來微重力實驗的地面原型飼養籠**：用半導體製冷片降溫到約 15°C 誘導蟄眠，再加熱喚醒，帶溫濕度監測、紅外攝影和多重安全保護。

**白話版開場（評委不是理科時用）：** 太空人在太空久了肌肉會變細、骨頭會變脆。有一種澳洲小動物叫脂尾袋鼩，每天會「睡一覺省能量」，睡的時候身體損失很小。科學家想研究牠，就需要一個能讓牠冷下來睡、暖起來醒、還能一直看著牠的籠子。我們做的就是這個籠子的地面試驗版。

**一句話創新點：** 實測發現冷端風扇不是越快越好，降到約 52% 時出風口從 18.6°C 降到 14.9°C。

**一句話定位：** 這是地面原型，不是航天產品；目前只做了空箱測試，沒有動物實驗。

**一句話局限：** 出風口約 15°C，但巢穴約 22°C，差約 7°C，還沒達到論文要求的艙內 15°C。

## 1b. 作品有什麼用

> 答法順序：**先用專業說法講，講完馬上用一句白話解釋。** 評委裡可能有不是理科的老師，白話讓所有人聽懂；專業說法讓懂行的評委知道你真的懂。各國科學展評審指南裡「這對現實生活有什麼用」「為什麼重要」「誰會受益」都是固定題。下表每格先「說」，再「白話」。

| 問題 | 答法 |
|---|---|
| 你這個作品到底有什麼用？ | **說：** 這是面向未來微重力蟄眠實驗的脂尾袋鼩地面原型飼養籠，用 TEC 雙向溫控（降溫誘導蟄眠、加熱喚醒），帶溫濕度監測、紅外影像和分級安全保護，給人工蟄眠研究提供硬體平台。**白話：** 太空人在太空久了肌肉會變細、骨頭會變脆；有些小動物會「睡一覺省能量」，睡的時候身體損失很小。要研究牠，先要有一個能讓牠冷下來睡、暖起來醒的籠子，我們做的是這個籠子在地面上的第一版。 |
| 它能幫到誰？誰會用？ | **說：** 直接用戶是空間生命科學和蟄眠生理的研究者；長遠受益的是長期載人深空任務的航天員，以及廢用性肌萎縮、骨質疏鬆的臨床研究。**白話：** 現在是給做研究的科學家用；將來可能幫到太空人，也可能幫到長期臥床的病人。（注意：病人那條是研究方向，不是說這個籠子能治病。） |
| 誰在乎小動物睡不睡覺？ | **說：** 研究價值在蟄眠期間的抗廢用性萎縮、抗骨質流失機制；文獻顯示冬眠動物的骨骼肌通過代謝重塑避免萎縮。**白話：** 重點不是牠睡覺，是牠睡覺時「肌肉骨頭不容易壞」這個本事。 |
| 不去太空，在地球上能用嗎？ | **說：** 系統本身是通用的小型可控環境平台：閉環溫控、多參數監測、CSV 數據記錄、紅外影像、異常自動停機，可以用在小動物、昆蟲、植物的溫度生理實驗。**白話：** 它就是一個會自己控溫度、記數據、拍夜視畫面、出事自己停的小箱子，學校實驗室也負擔得起。（邊界：降溫只到出風口約 15°C，箱內還沒那麼冷。） |
| 現在就能用嗎？還差什麼？ | **說：** 目前只完成空箱測試；巢穴約 22°C，未達論文要求的艙內 15°C；安全機制有已知漏洞（#36、#37、手動模式 #8）；動物實驗需要倫理審批。**白話：** 還不能放動物：箱子還不夠冷、有幾個安全問題要補、還要先拿到批准。我們先驗證的是「硬體能不能做到」。 |
| 這跟普通人的生活有什麼關係？ | **說：** 廢用性肌萎縮和骨質疏鬆在長期臥床者和老年人中很常見，和微重力下的生理變化相似；蟄眠的保護機制是潛在的轉化方向。**白話：** 老人、長期躺床的人也會肌肉變細、骨頭變脆，跟太空人很像，弄懂動物怎麼避免，將來可能變成新的治療思路。 |
| 做這個花了多少錢？貴不貴？ | **（答辯前自己算總數填這裡）** **說：** 全部用商用現成器件 + 開源硬件 + 3D 列印，主要成本是 ESP32 主控、TEC、H 橋、感測器、攝影機和 PLA 耗材，總共約 ___ 元。**白話：** 零件都是網上買得到的，比買一台商用動物恆溫箱便宜很多。 |
| 能不能做很多台、推廣？ | **說：** 可複製性好：器件都是現貨，結構件 3D 列印，固件和文檔都整理好了；擴展成多通道可以設對照組。簡介裡的六籠單元目前只是 CAD 設計。**白話：** 照著我們的資料就能再做一台；做幾台一起用，就能一台當對照。 |
| 跟直接買現成的恆溫箱比，好在哪？ | **說：** 商用恆溫箱多用壓縮機製冷，精度高但體積大、成本高、不能定制；我們用 TEC，可雙向溫控、可按實驗改，還自帶遠程監測、紅外影像和安全停機。**白話：** 現成的更準但大、貴、改不了；我們的小、便宜、能按這個實驗改。不比精度，比適合。 |
| 動物在裡面會不會痛苦？蟄眠有害嗎？ | **說：** 脂尾袋鼩是自發性每日蟄眠物種，蟄眠是正常生理行為；文獻記載甦醒時體溫回升 0.7–1.0°C/min，約 15 分鐘從約 15°C 回到 30–34°C，不造成長期損害。**白話：** 牠在野外本來每天都會這樣睡，醒得也快，不傷身。我們目前沒放動物，以後放也要先過倫理審批。 |
| 為什麼不直接用人做實驗？ | **說：** 人類沒有自發蟄眠能力，而且受倫理限制，必須先在動物模型裡確定機制和安全參數。**白話：** 人不會自己蟄眠，也不能拿人亂試，先在會蟄眠的動物身上弄清楚。 |
| 人真的能像動物那樣冬眠嗎？ | **說：** 人工誘導人類進入低代謝狀態仍在研究階段，還沒實現。**白話：** 現在還不能，這正是科學家在研究的；我們只是幫他們做工具。 |
| 什麼叫「地面原型」？ | **說：** 在地面驗證核心功能（溫控、監測、安全）的工程樣機，沒有經過飛行鑒定（振動、失重、輻射、真空等測試）。**白話：** 就是「上太空之前，先在地上做的試驗版」。 |
| 你們從這個項目學到什麼？ | **說：** ① 氣流熱負載：風量不是越大越好；② 結論要靠控制變量的對照實驗，我們兩次改結構都因變量沒控制住而無法歸因；③ 失效安全（fail-safe）設計：異常時設備要自動進入安全狀態。**白話：** 直覺會騙人；要比較就只能改一樣東西；出事時機器要自己停。 |
| 你們怎麼分工？ | **（三位成員答辯前對好，各自能講自己那塊的細節）** 例如：誰負責接線和硬體、誰負責程式和網頁、誰負責實驗和數據、誰負責報告和 CAD。 |
| 為什麼對這個題目有興趣？ | **（用自己的真實經歷講一句，不要背範例）** 例如：看到太空人回地球要人扶著走的新聞，好奇有沒有辦法；後來查到小動物蟄眠能保護肌肉。 |

## 2. 簡單概念題（最可能被問）

> 同樣先「說」專業定義，再「白話」解釋。

| 問題 | 答法 |
|---|---|
| 什麼是蟄眠（torpor）？和冬眠區別？ | **說：** 蟄眠是動物主動、可逆地降低代謝率和體溫的狀態。每日蟄眠持續數小時，冬眠以季節計、可持續數月；脂尾袋鼩能自發每日蟄眠。**白話：** 像手機開省電模式；蟄眠是睡幾個鐘頭，冬眠是一睡幾個月。 |
| 為什麼研究蟄眠和太空有關？ | **說：** 微重力下抗重力肌（如比目魚肌）發生廢用性萎縮，並伴隨骨質流失；文獻顯示冬眠動物骨骼肌通過代謝重塑避免廢用性萎縮。**白話：** 沒有重力，肌肉骨頭不用出力就會變細變脆，像腿打石膏幾個月會變細；但冬眠動物躺幾個月肌肉卻不太萎縮。 |
| 為什麼選脂尾袋鼩？ | **說：** 能自發每日蟄眠、不需季節誘導；成年 10–20 g；尾部儲脂可作非侵入的代謝指標；原生澳洲乾燥氣候，耐受資源受限環境。**白話：** 牠天天都會自己蟄眠，個子小，看尾巴胖瘦就知道牠的能量狀況，不用抽血。 |
| TEC 是什麼？原理？ | **說：** TEC1-12703 半導體製冷片，基於帕爾貼效應：直流電流過 P/N 型半導體時，一面吸熱、一面放熱；**改變電流方向，冷熱面互換**。我們用 BTS7960 H 橋切換方向，所以同一片既能製冷也能加熱。**白話：** 它是一個「熱量搬運工」，通電就把熱從一面搬到另一面；反過來通電就反過來搬。 |
| 為什麼用 TEC 而不是壓縮機？ | **說：** TEC 是固態器件，沒有運動部件、沒有製冷劑、無振動、可雙向；缺點是能效比（COP）低，熱端要散掉的熱比較多。**白話：** 冰箱的壓縮機又大又會震；TEC 很小很安靜，還能冷熱兩用，代價是比較費電。 |
| 為什麼熱端要散熱？ | **說：** 熱端排熱量 = 冷端吸熱量 + 輸入電功率；熱端溫度降不下來，冷熱面溫差有限，冷端溫度就跟著上升。**白話：** 跟冷氣一定要有室外機一樣，熱搬出來要有地方丟。 |
| 銅片有什麼用？ | **說：** 0.3 mm 紫銅片作均熱片，利用銅的高導熱率把 TEC 熱面集中的熱量橫向擴散，降低擴散熱阻，讓整塊散熱器底面參與散熱。冷面約 16–17°C 降到約 5–6°C（手測，沒有存 CSV，要如實說）。**白話：** 把一小團熱「攤平」到整塊散熱器上。 |
| bang-bang 控制是什麼？ | **說：** 開關式控制加死區：巢穴溫度高於「目標 + 死區」滿功率製冷，低於「目標 − 死區」滿功率加熱，區間內關閉。優點簡單可靠，缺點是溫度在死區內波動。**白話：** 像冷氣「到溫度就停、熱了再開」。 |
| 為什麼不用 PID？ | **說：** 07-23 上午試過 PI，調了兩個鐘頭：當時室溫 29–30°C、目標 28°C，溫差太小，PI 輸出一直偏低，13:07 改成開關式。正式 24→15°C 實驗溫差大，到時要換回 PI（步驟在 CONFIG_GUIDE §3.5）。**白話：** 溫差太小時那套「按差距算功率」的方法使不上力，就先用最簡單的開關法。 |
| PWM 是什麼？ | **說：** 脈寬調變：以固定頻率高速開關，用占空比（開的時間比例）調平均功率；TEC 經 H 橋用 PWM 調功率。冷端風扇是 4 線 PWM 風扇：電源一直接著，ESP32 只給控制線送 25 kHz 信號，風扇內部按占空比調轉速，所以 52% 是控制信號占空比，不等於 52% 轉速。**白話：** 像飛快地開關燈，開的時間長一點就亮一點。 |
| ESP32 是什麼？為什麼選它？ | **說：** 雙核、內建 WiFi 的低成本微控制器，同時跑控溫、Web 伺服器和 OLED，不需要另外的網關。**白話：** 一塊很便宜、能上網的小電腦板，一塊就能管溫度又能開網頁。 |
| DS18B20 是什麼？ | **說：** 數位溫度感測器，用 OneWire 單總線，每顆有唯一的 64 位 ROM 地址，我們按地址分配角色，12 位解析度（0.0625°C）。3 顆：巢穴（控溫）、活動區（監測）、出風口（過熱保護）。**白話：** 三根溫度計共用一條線，每根有自己的「身份證號」，所以分得清誰是誰。 |
| BME680 測什麼？ | **說：** 溫度、濕度、氣壓、氣體電阻。用溫濕度算露點做防結露警示；氣體只記錄原始電阻，不換算成 CO₂ 或空氣品質指數。**白話：** 一個小晶片同時量冷熱、乾濕和氣壓，用來判斷箱子裡會不會「出水」。 |
| 為什麼要紅外攝影機？ | **說：** 脂尾袋鼩夜間活動，用 940 nm 近紅外補光，人眼看不見，一般認為對夜行小動物干擾很小，不打亂晝夜節律。**白話：** 像夜視監控，黑暗中也能看到動物，又不會開燈吵醒牠。 |
| 什麼是露點、為什麼擔心結露？ | **說：** 露點是空氣在含水量不變下冷卻到飽和、開始凝結的溫度；我們用 BME680 溫濕度按 Magnus 公式計算，出風口 ≤ 露點 + 1°C 時警示。冷端鰭片比露點冷，必然凝露，水滴可能被吹向動物，所以做了警示和雙層網架空。**白話：** 夏天冰水杯外面出水珠就是結露。 |
| 為什麼要 3D 列印？ | **說：** PLA 熔融沉積列印，快速原型迭代、成本低；P1→P3 三輪靠它。**白話：** 改設計不用開模，印一個新的就能試。 |
| 什麼是 I²C？ | **說：** 兩線串列匯流排（SDA 數據線、SCL 時鐘線），每個設備有自己的地址；OLED 和 BME680 共用。**白話：** 兩條線像一條共用電話線，每台設備有自己的號碼。 |
| 看門狗（watchdog）是什麼？ | **說：** 一個獨立倒數的計時器。主程序每跑一圈就把它重置一次（叫「餵狗」），程序卡住、超過 7 秒沒餵，它就強制讓 ESP32 重啟。我們用 ESP32 自帶的任務看門狗：`esp_task_wdt_init(7, true)`。**為什麼要：** 程序卡死時 TEC 會停在最後狀態，如果剛好在全力製冷或加熱，箱子會一直冷下去或熱下去；有看門狗，最多 7 秒就重啟、重新控溫。接相機那幾天主循環被拖住，它真的觸發過重啟（LOGBOOK 07-24～07-28）。**邊界：** 它只管「程序卡死」，管不了「程序沒卡但邏輯算錯」，那要靠其他保護；重啟後自動恢復運行靠 10-04 加的斷電恢復，還沒上機拔電驗證。**白話：** 像一個「每 7 秒要按一次的按鈕」，程序正常會一直按，死機按不到，它就自動幫你重開機。 |

## 3. 項目題（中等難度）

**選型與數據**
- 為什麼選 12703 不選 12706？ → 對比測試：製冷速率 0.449 vs 0.414 °C/min，加熱 1.484 vs 1.305 °C/min；功耗約 36 W vs 72 W（12 V × 額定電流估算，沒實測），熱端壓力減半。關鍵一句：**12706 功率翻倍，製冷反而略差，說明瓶頸在熱端散熱，不在片子。**（邊界：這組是舊的比例控溫固件，每種只測一次。）
- 你們的最大發現？ → 風扇降速優於全速：全速 18.6°C，52% 時 14.9°C。**說：** 全速時氣流熱負載大，大量室溫空氣流過冷端，TEC 的製冷量被拿去冷卻新進空氣；降速後空氣在鰭片間停留更久、換熱更充分。**白話：** 風吹太快，空氣「來不及被冷到」就走了，像手在冰塊上快速划過不覺得冰，放著才冰。
- 52% 是最優嗎？ → **不能這麼說。**只證明「降速優於全速」；50% 檔只跑了不到 5 分鐘且還在下降，沒有做檔位掃描。
- 為什麼自動模式風扇還是 100%？ → 52% 是手動設定的結果，自動分支尚未改。（如實說，並列為下一步。）
- 數據量？ → P1–P3 共 18 份 CSV。

**達標程度**
- 達到目標了嗎？ → 出風口約 15°C 達到；巢穴約 22°C 沒達到。下一步查是箱體漏熱還是冷端換熱不足（目前沒有能歸因的數據）。
- 為什麼巢穴比出風口熱 7°C？ → 兩個猜測都沒證實也沒排除：① 箱體漏熱，冷氣到對角已被加熱；② 冷端換熱面積小（約 16 cm²），冷量傳不到空氣裡。XPS 內襯（約 08-22）和鋁板（08-29）試過，但條件混雜，數據說明不了問題。
- 現在這台箱子巢穴多少度？ → 22°C 是 08-01（P2，**還沒裝 XPS**）測的；裝 XPS 後沒在 52% 下測過（08-26 那次風扇 100%、室溫高 3°C、探頭接觸不良）。如答辯前補測了，就報新數字。
- 為什麼停止優化？ → 兩次改結構都沒拿到可歸因的數據，再改要重新列印重新測，時間不夠。09-03 和指導老師開會定的，09-10 落實；剩餘時間轉做安全、監測和文檔。

**安全**
- 出事怎麼辦？ → 五層：感測器連續 3 次無效（約 12 秒）停機；出風口 ≥ 50°C 停機；巢穴超出 5–35°C 只關 TEC、風扇繼續換氣；硬體看門狗 7 秒；斷電參數保存、來電自動恢復。另外兩個小機制：出風口到 40°C 起逐步降功率；TEC 關掉後風扇再轉 10 秒防熱回灌。
- 保護可靠嗎？ → 主動講已知漏洞：DS18B20 上電值 85.0°C 會被當真溫度，08-26 因此誤急停一次（#37）；本來缺一顆探頭、之後整條線全掉時不會急停（#36）；手動模式全部保護不生效（#8）。演示前用 `/diag` 和晃線檢查規避，動物實驗前必須改代碼。
- 斷電恢復驗證了嗎？ → 10-04 起加入。**答辯前拔電試過**就說「驗證過」；沒試就說「代碼已實作、有單元測試，還沒上機拔電驗證」，不要說「正在驗證」。
- 動物會不會凍死或熱死？ → 目前沒有動物；巢穴超出 5–35°C 安全範圍會關 TEC。

**結構/軟體**
- 兩塊 ESP32 怎麼配合？ → 主控管溫控，S3 相機管影像，只通過 WiFi 鬆耦合，一塊壞了不影響另一塊的控溫。
- 怎麼驗證程式沒問題？ → 桌面端單元測試 41 項通過（注意：測試是鏡像邏輯，不是直接測硬體）。
- 製冷/加熱方向反了怎麼回事？ → 11-02 重新燒錄後發現網頁「製冷」實際在加熱，原因應是之前拆裝動過線。這次不動線，在程式裡對調兩個 PWM 腳（製冷 GPIO25、加熱 GPIO26），重新燒錄上機確認方向正常。教訓：改代碼和改接線只能二選一。

## 4. 評委通用題（來自搜索到的比賽指南）

| 類型 | 問法 | 建議答法 |
|---|---|---|
| 來源 | 想法從哪來？ | 看到航天員肌肉萎縮的問題 + 蟄眠文獻 → 想做地面載體；說出自己的選擇（TEC、風路）。 |
| 誰做的 | 誰幫了你？ | 如實：老師（指導老師王恒）、查新、文獻；風扇降速和加銅片都是聽了建議才試的，要如實說，但測試和數據分析是自己做的。自己做的部分要能講細節（接線、程式、測試）。 |
| 重來 | 如果重做會怎樣？ | 先做箱體隔熱和氣密、早做對照實驗（開關風扇、有無 XPS），再選器件；風扇做檔位掃描。 |
| 下一步 | 接下來做什麼？ | 巢穴局部冷區、自動風扇降速、加 PID、真正動物預實驗（需倫理審批）、多通道對照。 |
| 重要性 | 成果有什麼意義？ | 低成本地面原型、可轉為普通實驗室小動物箱；驗證風路降速這個非直觀發現。白話說法見 §1b。 |
| 決策 | 為什麼選這個設計？ | 用對比數據說話：12703 vs 12706、12 V vs 8.5 V、風扇 100% vs 52%（都有 CSV）。銅片只有手測冷面，出風口的改善同時換了密封箱，不要當成對照實驗講。 |
| 如果 | 如果結果相反呢？ | 例：如果降速沒改善，就說明是熱端瓶頸，改看散熱器。 |
| 與現有 | 和市面產品比？ | 商用恆溫箱/壓縮機方案貴且大；我們是低成本學生原型，不比精度，比可定制和可監測。 |
| 局限 | 不足在哪？ | 直接說：無動物實驗、巢穴未達標、單通道無對照、手動模式無保護。誠實比硬撐更加分。 |

## 5. 刁難題（準備一兩個就夠）

1. **「沒有動物實驗，你憑什麼說它能誘導蟄眠？」**
   → 我們不聲稱能誘導。目標溫度來自文獻（環境 <18°C 誘導傾向顯著增加，論文流程 24→15°C）；本項目是**地面硬體原型**，驗證的是能否穩定提供該環境；動物實驗需倫理批准，是下一階段。
2. **「箱內都沒到 15°C，這個原型算成功嗎？」**
   → 部分成功：出風口達標，巢穴差 7°C。我們如實披露，並提出歸因路徑（漏熱 vs 換熱不足）。
3. **「微重力下氣流和冷凝水完全不同，你怎麼保證？」**
   → 保證不了。地面原型只解決溫控與監測；微重力下的熱對流、水滴行為需要另行驗證，簡介裡的定向氣流和防漏飲水嘴是設計思路，不是已驗證結果。
4. **「TEC 效率低，太空能耗大怎麼辦？」**
   → 12703 額定約 36 W，是選它的理由之一（比 12706 少一半）；太空電源預算要在正式載荷階段評估。
5. **「bang-bang 會讓溫度波動，對動物有害嗎？」**
   → 目前只做空箱，沒有量化波動幅度對動物的影響；改進方向是 PID 或更窄死區。
6. **「你的數據有多可靠？」**
   → 重複性有限：各批次室溫不同（24–28°C），「5–6°C 冷面」為手測、沒有 CSV，14.87°C 那組只測過一次；關鍵結論（降速優於全速）有 CSV 支撐。
7. **「風小了出風口是更冷，但送進箱子的總冷量是不是反而少了？」**
   → 有可能。帶走的熱量約等於風量 × 溫差，出風口溫度低不代表總冷量多。數據上巢穴只從約 23.3 降到 22.2°C，降得比出風口少得多，跟這個解釋一致。所以下一步要做檔位掃描，同時看出風口和巢穴，而不是只看出風口。

## 5b. 發散補充（關鍵詞搜索得到的方向）

**動物倫理（評委很可能問）**——有高中生動物實驗項目因違反動物使用標準被取消資格的先例（[NBC News](https://www.nbcnews.com/news/amp/wbna18789038)），有些賽事也禁止活體脊椎動物實驗（[Daily Lobo](https://www.dailylobo.com/article/2007/06/cruel_live_animal_projects_should_be_banned_at_fairs)）。
- 「你們用了動物嗎？」→ **沒有**，只做空箱測試；動物實驗需倫理審批，不在本賽事範圍。
- 「3R（替代、減少、優化）怎麼體現？」→ 先用空箱把硬體調好，減少未來動物用量；紅外攝影不打擾夜間活動、雙層網架空不碰冷凝水是優化福利的設計；封閉巢穴、紋理內壁按實物講（沒裝就說設計構想）。LED 燈帶目前只能手動調光，**不要說已經有 12L:12D 晝夜節律**。
- 「植入晶片手術呢？」→ 是未來完整方案（DSI 遙測），不是現在做的。

**選型思路（為什麼選這個器件）**——答題維度：性能、成本、可靠性（自己實測）、生態/開發難度、功耗。
- ESP32：自帶 WiFi、庫豐富、便宜；DS18B20：一線多顆、防水探頭現成；TEC1-12703：自己對比測試出來的，不是隨便選。
- 句式：「我們買了兩種都測了，數據是……所以選……」，比「網上說好」有力。

**太空生物載荷常見關注點（背景知識）**
- 為什麼選小型囓齒類？→ 體型小、重量輕、維護容易，飛行硬體好配套；脂尾袋鼩 10–20 g。
- 微重力 / 陌生環境可能讓動物應激 → 所以設計封閉巢穴、可抓握內壁，參考 NASA 囓齒類棲息艙的做法（見 [ISS Rodent Habitat 環境豐容](https://www.aminer.org/pub/622883795aee126c0fe24315/environmental-enrichment-in-the-iss-rodent-habitat-hardware-system)）。
- 太空實驗通常要有**對照組**（地面組，甚至離心機 1 g 組）→ 我們單通道，**做不了對照**，這是已知局限。
- 雙重價值：服務深空探索 + 地面臨床（骨質疏鬆、肌肉萎縮）。
- 其他可能被問：功耗與載荷重量限制、飲水與排泄物在失重下怎麼處理（我們只有設計構想，沒驗證）、輻射、發射振動——一律答「地面原型階段未涵蓋，屬後續工程驗證」。

## 6. 答辯技巧（來自搜索結果的要點）

- 準備 **3 分鐘 / 5 分鐘 / 10 分鐘**三個版本；5 分鐘版最重要。
- 評委通常先問簡單題建立信心，再追問你陳述裡沒講清楚的地方，所以陳述時就把「來源、數據、不足」講清楚。
- 評委要確認是**你自己做的**：圖、接線、程式、數據都要能指著說。不要背稿，被追問就露餡。
- 不確定就說「這個我們沒測過，推測是……，下一步會驗證」，不要編。
- 承認局限 + 給出改進路徑，通常比回避得分高。
- 模擬答辯：找同學扮評委，把本檔第 2、3 節的問題打亂各問一遍。
- 實物演示前按 `docs/PROGRESS.md` 的「演示前 5 分鐘檢查」走一遍；演示時**不要用手動模式**。
