# TEC 蟄眠實驗溫控系統

ESP32 開關式（bang-bang）溫控系統，用於脂尾袋鼩（fat-tailed dunnart）蟄眠實驗。3 顆 DS18B20 分角色監控，Web 儀表板 + OLED 即時顯示 + CSV 資料匯出。

> **項目狀態（2026-09-10 收尾鎖版；2026-09-26 文檔複核）：** 溫度優化凍結（15°C 工程甜點）；**已裝機（2026-10-04 用戶確認）**= LED 燈帶+MOS、BME680、HEPA 濾芯 + 顆粒活性炭、吸附墊、定向氣流、雙層不鏽鋼網、隔水墊、相機進箱；集水結構不做；鋁板裝過後已拆除；SCD40/MQ/INA219/蜂鳴器已砍。2026-10-04 解凍改碼：斷電自動恢復（#31）、BME680 溫濕壓 1 Hz、防結露警示。實驗數據見 `docs/EXPERIMENTS.md` §9、§10。演示前必做檢查見 [演示前檢查](#演示前檢查)。

### TEC 型號選擇說明

12703 vs 12706 對比測試結果（詳見 `TEC分析報告.html`）：

| 指標 | 12706 | 12703 |
|------|-------|-------|
| 標稱電流 | 6A | 3A |
| 製冷速率 | 0.414 °C/min | **0.449 °C/min** |
| 加熱速率 | 1.305 °C/min | **1.484 °C/min** |
| 總功耗（估算，12V×額定電流） | ~72W | ~36W |

> 速率按 CSV 時間戳時長計算（`TEC分析報告.html` 曾把行數當秒數，加熱速率寫成 1.297/1.419，以本表為準）。這組數據（P1，07-22）由**舊版韌體**採集：當時是比例控溫（風扇隨溫差變速，預設目標 20/28°C，commit `ab6141f`），07-23 才改為現在的開關式（`18b8bd4`）。

12703 在同樣散熱條件下表現更好，原因：
- 總功率低 → 熱端散熱壓力小 → 冷端能維持更低溫
- 電流剛好匹配系統電源輸出範圍
- 程式不須任何修改，直接可用

### 實測性能（2026-08-01，室溫 24–25°C）

封閉箱體（20×24×16cm）實測，12V 供電（原始數據：`P2-有铜片无隔温板/P2-有铜片无隔温板_0801_风扇降速出风14.9度.csv`）：

| 條件 | 出風口最低溫 | 說明 |
|------|------------|------|
| 冷端風扇 100% | 18.6°C | 氣流熱負載大，冷端被吹熱（穩態平台） |
| 冷端風扇 50%（手動） | 17.3°C | 只跑了 4:44，讀到 17.3 時仍在下降，未到穩態 |
| **冷端風扇 52%（手動，持續 23 分鐘）** | **14.9°C** | 出風口達 14.9°C；**巢穴仍 22°C，箱內環境未達論文 15°C** |

> 50%/52% 都是網頁滑條手動設定；未手動時自動分支恆為 100%。18.6→14.9°C 的改善來自**風扇降速**（同一檔 P2 數據，已裝銅片），不是銅片。

**關鍵發現：冷端風扇風量 = 熱負載**

風扇全速時，每秒鐘把大量室溫空氣送到冷端面前，TEC 被迫把泵熱能力花在"冷卻新進空氣"上，冷端溫度被拉高（出風口最低只到 18.6°C）。降速後（50–52%），空氣在鰭片內停留更久、換熱更充分，冷端能維持更低溫（14.9°C）。**風扇不是越快越好。** 但 50% 檔時間太短，數據只能支持「降速優於全速」，不能證明 52% 就是最優點。

**已知瓶頸：箱內溫度分布不均**

出風口 14.9°C 但巢穴（對角最遠端）仍 22°C，相差 7°C。論文的 15°C 指的是**艙內環境溫度**，所以只有出風口到 15°C 不算達標。原因：3D 列印箱壁薄（2-3mm PLA）漏熱嚴重，冷氣循環到最遠端時已被環境熱量加熱。解決方案：
1. **箱內壁 XPS 20mm 保温板**（約 2026-08-22 裝好，內膽全縫鋁箔膠帶氣密）— P3 三份數據都有 XPS。0826 有巢穴數據但結果不理想：連續製冷 38:35（16:35–17:13）期間巢穴 26.10→26.50 沒降（當時風扇 100%，是混雜因素）；0831 巢穴探頭缺失
2. **巢穴局部冷區** — 用 XPS 剩料把巢穴隔成小空間（約 1/6 體積）直接導冷風，小空間降溫容易 6 倍

**⚠️ 冷凝水風險（出風口降到 15°C 附近後的新問題）：** 出風口 14.9°C 已低於室溫 24-25°C + 高濕度下的露點（約 18-20°C），冷端鰭片**必然凝露**，水滴可能被氣流吹向動物。**2026-09-10 鎖版定：不做集水盤/排水結構**（風險已知，見 LIMITATIONS.md #25）。

**熱端配置（驗證有效）：** 0.3mm 銅片夾在 TEC 熱面與散熱器之間（兩面塗散熱膏）+ 7cm 5500RPM 風扇。無銅片時 TEC 冷面約 16–17°C，加銅片後約 5–6°C（手測回憶值，無 CSV 記錄）；出風口無銅片只到約 24–26°C（P1 最低 24.07），加銅片後風扇 100% 約 18.6°C——銅片把 TEC 熱量橫向攤平，讓整個散熱器底面參與散熱。

**電源：** 12V 額定（TEC1-12703 設計電壓），無 15.8V 升壓需求。

### FireBeetle 2 ESP32-E D-pin 陷阱

**板標 D 編號 ≠ GPIO 編號！**

| 板標 | 實際 GPIO | 可用？ | 說明 |
|------|----------|--------|------|
| D2 | 25 | ✅ | TEC RPWM（加熱）|
| D3 | 26 | ✅ | TEC LPWM（製冷）|
| D7 | 13 | ✅ | LED 燈帶 PWM（經 IRLZ44N 驅動 12V 燈帶；本板無 D4/GPIO27 引腳，見 DFRobot wiki DFR0654） |
| D5 | 0 | ❌ Strapping | 勿用 |
| D8 | 5 | ❌ Strapping | 勿用 |
| D9 | 2 | ❌ Strapping | 勿用（內建 LED）|
| **D12** | **4** | ✅ | **DS18B20 接這裡** |
| **D13** | **12** | ❌ Strapping | **接了 4.7kΩ 上拉 = ESP32 變磚** |

## 系統架構

**兩個獨立韌體目標（各自 `pio run`）：**

```text
┌─ 主 ESP（FireBeetle 2 ESP32-E）─ src/main.cpp ─┐
│  TEC 溫控 + 3×DS18B20 + BME680 + OLED + Web 儀表板 │
│  WiFi AP：ESP32-TEMP（192.168.4.1）           │
└───────────────────────────────────────────────┘

┌─ 相機（DFR1154 ESP32-S3 AI Camera）─ camera/src/main.cpp ─┐
│  MJPEG 串流（VGA 640×480）+ IR/LED 控制                   │
│  WiFi STA：連手機熱點（失敗回退 ESP32-TEMP），mDNS：esp32-cam │
└──────────────────────────────────────────────────────────┘
```

### 主 ESP 程式結構

```
src/main.cpp  (單一 Arduino sketch，1240 行)

├── 硬體層
│   ├── OneWire + DallasTemperature → 3×DS18B20
│   ├── LEDC PWM ×3 → FAN / TEC_L / TEC_R
│   ├── GPIO OUT → TEC_EN
│   ├── I2C HW → SSD1306 OLED
│   └── I2C HW → BME680（Adafruit BME680 驅動，與 OLED 並線）
│
├── 控制層
│   ├── readSensor() — 非阻塞轉換狀態機（750ms）+ EMA 濾波
│   ├── controlTemp() — 多段安全保護 + 開關控制（bang-bang）
│   ├── setTecPwm() — 0~1.0 歸一化功率 → 0~1023 PWM
│   ├── emergencyStop() — 斷電並關閉系統（需在網頁重新開啟）
│   └── bmeInit()/bmeTick() — BME680 非阻塞讀取（溫濕壓 1 Hz、Gas 每 10 秒）；updateCondRisk() — 防結露警示
│
├── 網路層
│   ├── WiFi：純 AP（預設）或 STA+AP 備援
│   └── WebServer port 80（8 個路由：/ /data /diag /control /test /strip /light /camenable）
│
└── 顯示層
    ├── INDEX[] PROGMEM — SPA 儀表板（HTML+CSS+JS inline）
    └── updateOLED() — SSD1306 狀態顯示
```

### Loop 狀態機

`loop()` 每個迭代依序執行：

1. **`esp_task_wdt_reset()`** — 餵 7 秒硬體看門狗
2. **`server.handleClient()`** — 非阻塞 HTTP（路由處理函式在 loop 內同步執行）
3. **斷線後備守衛** — `systemOn && sensorInit && nanCount >= 3` → `emergencyStop()` + `saveState()`
4. **風扇延遲** — 系統關閉後保持 78% 風扇 10 秒（吹散餘熱），然後關閉
5. **DS18B20 重掃描** — 每 10 秒嘗試（**任一探頭缺失**時：`!dsOk || !nestOK || !roomOK || !ventOK`）
6. **`readSensor()`** — 每 2 秒觸發一次；因轉換要分兩次呼叫，實際約 **4 秒**才出一筆新溫度
7. **`bmeTick()`** — BME680 非阻塞讀取（溫濕壓 1 Hz、Gas 每 10 秒），接著 `updateCondRisk()` 更新防結露警示
8. **OLED** — 每 5 秒探測 0x3C（熱插拔），每 2 秒刷新畫面
9. **EEPROM 去抖保存** — `/control` 改參數後 750ms 才寫入
10. **mDNS 重查相機 IP** — 未確認時每 5 秒、確認後每 60 秒

`readSensor()` 內部狀態機：
```
convPending=false → requestTemperatures() → 設 convPending=true
convPending=true  → 等 750ms → 讀取 → convPending=false
```

## 初始設定

### 1. 裝 PlatformIO

```bash
# 如果還沒裝 PlatformIO CLI
pip install platformio
```

或在 VS Code 裝 PlatformIO IDE 擴充套件。

### 2. 首次編譯前確認

- [ ] `platformio.ini` 中的 board 是 `esp32dev`
- [ ] DS18B20 的 ROM 位址與你手上的感測器一致（見下方）
- [ ] 4.7kΩ 上拉電阻已焊好

### 3. 燒錄

```bash
pio run --target upload
```

首次燒錄完成後，打開 Serial Monitor（115200 baud）確認輸出：
```
[DS18B20] 就緒 巢穴=1 活動=1 出風=1
[WiFi] 模式=純AP, IP: 192.168.4.1
[Server] OK
```

### 4. 更換感測器時的 ROM 位址更新

如果換了其中一顆 DS18B20，需要更新 `src/main.cpp` 中的對應常數：

```cpp
DeviceAddress nestAddr = {0x28, 0xXX, 0xXX, ...};  // 改成新的 ROM
```

如何取得新位址：看 Serial Monitor 在 `doScan()` 時輸出的 16 位十六進位碼。

## WiFi 與網頁儀表板

### 連線

| 項目 | 值 |
|------|-----|
| SSID | **ESP32-TEMP** |
| 密碼 | **12345678** |
| IP | **192.168.4.1** |

預設（`wifiMode=0`）ESP32 開的是獨立 AP，手機/電腦直接連上去，不經任何路由器。連上後瀏覽器打開 `http://192.168.4.1`。也可切到 STA+AP 備援（見 `/control` 的 `wifi` 參數）。

### 儀表板功能詳解

#### 頂部狀態列
- 綠點 = 系統正常 → 時間戳
- 紅點 = 感測器異常 → 錯誤訊息

#### 三感測器卡片
- 紅框 = 巢穴（溫控基準）
- 藍框 = 活動區（環境監測）
- 橘框 = 出風口（安全保護）
- 每張卡片即時顯示溫度

#### 溫度趨勢圖
- Canvas 繪製，自動縮放 Y 軸
- 電腦版：三張圖並排（巢穴 / 活動區 / 出風口）；手機版：一張圖 + 下方三個切換按鈕
- 紅/藍/橘線對應三個感測器
- 最新一筆讀值標在曲線末端
- 「導出 CSV」和「清除記錄」按鈕在圖表標題列

#### 箱內環境（BME680）
- 溫度 / 濕度 / 露點 / 氣壓 / 氣體電阻（kΩ）/ 相對基線（%）；未接時顯示 `--`、狀態「未接」
- 溫濕壓約 1 Hz（加熱器關）；Gas 每 10 秒一筆（只在該筆開加熱器 320°C/150ms）
- 開機前 10 分鐘為 Gas 燒機期，氣體數值勿引用
- **防結露警示（僅警示，不影響控溫）：** 出風口 ≤ 露點 + 1°C 時頂部出現「💧 結露風險」橫幅、OLED 出風口行右側顯示 `DEW`；回到 > 露點 + 2°C 才解除。BME680 離線或 30 秒內沒有成功讀數時不判斷。出風口量的是氣流溫度，冷端鰭片表面更冷，警示可能偏晚

#### 系統控制區
- **開啟/停止系統** — 總開關
- 狀態 pill：待機 / 製冷中 / 加熱中 / 維持中
- **製冷/加熱 pill** — 點擊會切到**手動模式**並以 **78% 功率**（`/test?cool=200` / `heat=200`）驅動 TEC。⚠️ 手動模式下**所有自動保護（探頭斷線、出風口過熱）都不執行**，直到切回自動或重新開啟系統
- **切換手動/自動模式** — 手動模式下 `controlTemp()` 不執行，TEC 停在切換那一刻的狀態（若正全力製冷就會一直製冷）

#### 目標溫度設定
- 目標溫度（10–40°C）：拉條 ⊕ 數字輸入框 ⊕ 滾輪
- 維持範圍（0.01–3°C）：同上
- 提示行：「巢穴 ＞X°C 製冷 | ＜Y°C 加熱 | 中間不動作」
- 數字框可直接打任意小數值，按 Enter 生效
- **打字時不會被 poll 覆蓋**（focus 鎖定，blur 解鎖）

#### 安全保護設定
- 巢穴最低溫（0–20°C）
- 巢穴最高溫（20–50°C）
- 出風口上限（40–80°C）
- 出風口超過上限 → 系統立即斷電（必須手動重啟）
- 注意：網頁上最低（0–20）與最高（20–50）範圍不相交，**不可能設反**；真正要注意的是**目標溫度必須落在最低與最高之間**，否則會一直走「巢穴極端溫度」分支（TEC 關閉）

#### 風速控制
- 手動風速 0–100%（拉條 + 百分比顯示）
- 一拖動滑條，伺服器端 `fanManual` 就會**一直保持**在你設的值，直到按「停止系統」或重新開啟系統；TEC 仍由自動邏輯控制。**冷端 52% 就是靠這個方式設定的**
- （前端另有 3 秒的顯示鎖 `fm`，只是避免輪詢把滑條數字覆蓋回去，不代表釋放控制權）

#### 更新頻率
- 實際預設每 **1 秒**輪詢一次（相機串流開啟時 5 秒）
- 「更新頻率」滑條（預設 1 秒）可調 1–10 秒；相機開啟時至少 5 秒（2026-09-26 修正，之前滑條會被覆蓋）

## 感測器角色與 ROM 位址

系統**不依賴匯流排掃描順序**辨識感測器，而是比對 ROM 出廠唯一位址：

| 角色 | ROM 位址 | 用途 |
|------|---------|------|
| 🏠 **巢穴** (Nest) | `28559122000000D6` | **溫控基準** — 製冷與加熱都看這顆 |
| 🌡 **活動區** (Room) | `284F59220000005E` | 純監測，不參與溫控邏輯 |
| 🌬 **出風口** (Vent) | `2820D720000000D7` | 硬體安全 — 過熱緊急斷電 |

### 辨識新感測器

1. 接上新 DS18B20 → 上傳程式 → 看 Serial Monitor
2. `doScan()` 會印出每個裝置的 ROM 位址和對應的角色
3. 認不到的會顯示 `[?]` → 把該 ROM 碼更新到 `src/main.cpp`

### 斷線行為

- 任一感測器斷線 → 對應溫度設為 `NAN`（`getTempC()` 斷線回傳 -127，被 -55~85°C 範圍檢查剔除）
- 網頁卡片顯示 `---`
- 自動模式下，**任一探頭**（巢穴/活動區/出風口）連續 3 次讀不到（約 12 秒）→ `emergencyStop()` + `saveState()`，需在網頁重新開啟
- 三探頭原本都在線時整條匯流排斷開，同樣走上面的 NaN 路徑約 12 秒急停；只有在 `doScan()` 已掃到 0 個設備（`dsOk=false`）時，`readSensor()` 直接 return，才不會急停（LIMITATIONS #36）
- ⚠️ **手動模式下以上保護全部不執行**
- ⚠️ DS18B20 剛上電時會回傳 **85.0°C** 預設值，範圍檢查只剔除 >85，85.0 會被當成真溫度（0826 數據的 85.00 尖峰與一次誤急停即此原因，LIMITATIONS #37）。看到 85.00 = 探頭線接觸不良

## 溫控邏輯詳解

### 控制流程（`controlTemp()`）

```
系統開啟 且 非手動模式（systemOn && !tecManual && !manualMode）？
  ├── NO → return（不動作，下面所有保護都不執行）
  └── YES ↓

巢穴/活動區/出風口 任一讀不到（NAN）？
  ├── YES → nanCount+1；連續 3 次（約 12 秒）→ emergencyStop() + saveState()；否則本輪 return
  └── NO ↓（nanCount 歸零）

出風口 ≥ ventMax（預設 50°C）？
  ├── YES → emergencyStop() + saveState() → 系統關閉，需在網頁重新開啟
  └── NO ↓

巢穴 < safeMin（5°C）或 > safeMax（35°C）？
  ├── YES → 關 TEC，風扇 100%（過熱）/ 24%（過冷，setFan(60)）
  └── NO ↓

熱節流：出風口 > ventMax − 10 → 功率 = (ventMax − 出風口)/10，否則 100%

巢穴 > 目標溫度 + 維持範圍？
  ├── YES → 製冷（上述功率），風扇 255 全速（**實測最優為手動 52%，見下方警告**）
  └── NO ↓

巢穴 < 目標溫度 - 維持範圍？
  ├── YES → 加熱（上述功率），風扇全速
  └── NO → 維持：關 TEC；剛從製冷/加熱切出時風扇 78% 吹 10 秒，然後關閉
```

### 開關控制（bang-bang）

TEC 在超出維持範圍時以 **100% 功率**運行（出風口接近上限時由熱節流降功率），進入範圍內後完全關閉。自動分支的風扇在製冷/加熱時都是全速；TEC 關閉後延遲 10 秒（78%）吹散餘熱，然後關閉。

> ⚠️ **實測修正（2026-08-01）：** 冷端循環風扇全速（100%）會把冷端吹熱（出風口最低 18.6°C），手動降到 52% 時出風口可達 14.9°C。**降速優於全速**；但 50% 檔只測了不到 5 分鐘、仍在下降，數據不足以證明 52% 就是最優點。加熱時風扇維持全速。熱端散熱風扇不受此限，維持全速。
>
> ⚠️ **代碼未同步（2026-09-10 確認）：** `controlTemp()` 製冷/加熱分支實寫 `setFan(255)`，**自動跑達不到 14.9°C**；要重現實測最佳值須在網頁手動把風扇設到 52%。鎖版決定不改代碼，演示前手動設定即可，詳 [LIMITATIONS.md](LIMITATIONS.md) #34。
>
> **斷電重啟（2026-10-04 修正）：** `setup()` 在 `loadState()` 之後，若上次為運行狀態就呼叫 `startAll()`，TEC_EN 會重新拉高，重啟後自動恢復控溫。緊急停機會把 `systemOn=false` 寫入 EEPROM，所以急停後重啟**不會**自動啟動。（尚未在實機上驗證。）

### 演示前檢查

鎖版不改代碼，以下靠人工確認（連上 `ESP32-TEMP` 後用瀏覽器操作）：

1. **方向測試**：打開 `http://192.168.4.1/test?cool=255&heat=0&en=1`，約 30 秒後摸 TEC 貼冷端換熱器那面應變冷；測完回主頁按一次「停止系統」恢復自動
2. **探頭測試**：打開 `http://192.168.4.1/diag`，`deviceCount` 應為 3；輕晃三根探頭線，主頁溫度若跳成「斷線」 或 `85.00` = 接觸不良，重新插牢
3. **任何重啟後**：確認網頁狀態與重啟前一致（2026-10-04 起運行中斷電會自動恢復；急停後不會）
4. **演示中不要用製冷/加熱小按鈕**：那是手動模式，所有保護都停用
5. **風扇**：開啟系統後，把手動風速滑條拖到 52%

## OLED 螢幕

### 接線（4 線）

| OLED-2864 腳 | 接線 | FireBeetle |
|-------------|------|-----------|
| VCC | 紅 | 3.3V |
| GND | 黑 | GND |
| SCL | 黃 | GPIO22（SCL）|
| SDA | 藍 | GPIO21（SDA）|

GPIO21/GPIO22 是 FireBeetle 預設 I2C 腳，與其他功能不衝突。

### 顯示內容

```
Nest:     29.12C
Room:     29.34C
Vent:     29.56C
────────────────────
Cooling    Fan:100%
Tgt:28.0C  Auto
```

- 上半部：三通道即時溫度（2 位小數），斷線顯示 `---`；結露風險時 Vent 行右側多一個 `DEW`
- 分隔線
- 左下：當前狀態（Cooling / Heating / Idle / OFF）+ 目標溫度
- 右下：風扇百分比 + 自動/手動模式

每 2 秒刷新。

### 熱插拔自動恢復

OLED 支援熱插拔恢復（`e9c6829`）：
- 啟動時掃描 I2C 匯流排並印出所有地址（僅供排錯）
- `loop()` 每 5 秒探測一次 0x3C，更新 `oledOnline` 狀態
- 若 OLED 斷線 → 自動呼叫 `u8g2.begin()` 重新初始化，無需重啟設備

## API 完整文件

Port 80，純 AP 模式下 IP `192.168.4.1`。

### `GET /` — 儀表板

回傳內嵌 HTML SPA（PROGMEM）。Content-Type: `text/html; charset=utf-8`。

### `GET /data` — 即時數據

回傳 JSON：

```json
{
  "ok": true,
  "nest": 29.12,
  "room": 29.34,
  "vent": 29.56,
  "sensorCount": 3,
  "fanSpeed": 100,
  "cooling": false,
  "heating": false,
  "systemOn": true,
  "manualMode": false,
  "camEnabled": false,
  "camIP": "192.168.4.2",
  "targetTemp": 28.0,
  "hysteresis": 0.50,
  "safeMin": 5.0,
  "safeMax": 35.0,
  "ventMax": 50.0,
  "wifiMode": 0,
  "bmeOk": true,
  "bmeT": 27.85,
  "bmeH": 62.3,
  "bmeP": 1009.4,
  "bmeGas": 35.2,
  "bmeGasRel": 100,
  "bmeDP": 19.9,
  "condRisk": false
}
```

| 欄位 | 類型 | 說明 |
|------|------|------|
| `nest` | float / null | 巢穴溫度 °C（EMA 濾波後值，已含偏移） |
| `room` | float / null | 活動區溫度 °C |
| `vent` | float / null | 出風口溫度 °C |
| `sensorCount` | int | 實際 ROM 識別到的感測器數量 |
| `fanSpeed` | int | 風扇 PWM（0-255），網頁轉為 % |
| `cooling` | bool | 製冷中？ |
| `heating` | bool | 加熱中？ |
| `systemOn` | bool | 系統總開關 |
| `manualMode` | bool | 手動模式？ |
| `targetTemp` | float | 目標溫度 °C |
| `hysteresis` | float | 維持範圍 °C |
| `safeMin` / `safeMax` | float | 巢穴安全範圍 °C |
| `ventMax` | float | 出風口斷電閾值 °C |
| `camEnabled` / `camIP` | bool / string | 相機開關；相機 IP（未經 mDNS 確認時為預設 192.168.4.2） |
| `wifiMode` | int | 0=純 AP，1=STA+AP 備援 |
| `bmeOk` | bool | BME680 是否在線 |
| `bmeT` / `bmeH` / `bmeP` | float / null | 溫度 °C / 濕度 % / 氣壓 hPa |
| `bmeGas` / `bmeGasRel` | float / null | 氣體電阻 kΩ / 相對基線 %（慢速 EMA 當 100%） |
| `bmeDP` | float / null | 露點 °C（Magnus 公式） |
| `condRisk` | bool | 防結露警示：出風口 ≤ 露點+1°C 進入、> 露點+2°C 解除；BME 離線/過期時恆為 false。僅警示 |

溫度與 BME 欄位在感測器缺失時為 `null`。錯誤時回傳 `{"ok":false,"message":"..."}`。

### `POST /control` — 控制指令

| 參數 | 範圍 | 說明 |
|------|------|------|
| `system` | 0/1 | 系統總開關 |
| `manual` | 0/1 | 切換手動/自動模式 |
| `targetTemp` | 10–40 | 目標溫度 °C |
| `hysteresis` | 0.01–3 | 維持範圍 °C |
| `safeMin` | 0–20 | 巢穴最低安全溫 |
| `safeMax` | 20–50 | 巢穴最高安全溫 |
| `ventMax` | 40–80 | 出風口斷電閾值 |
| `nestOff` | -5~5 | 巢穴感測器校準偏移 °C（網頁無此 UI，只能直接發請求） |
| `roomOff` | -5~5 | 活動區感測器校準偏移 °C |
| `ventOff` | -5~5 | 出風口感測器校準偏移 °C |
| `wifi` | 0/1 | **WiFi 模式**：0=純 AP（默認，最穩定），1=STA+AP备援（先連指定 WiFi，失敗切 AP）。切換後系統自動重啟。 |
| `ssid` | 字串 | 搭配 `wifi=1`：要連接的 WiFi 名稱，存 EEPROM[35] |
| `pass` | 字串 | 搭配 `wifi=1`：WiFi 密碼，存 EEPROM[68] |

參數可組合。範例：

```
POST /control?system=1&targetTemp=28.0&hysteresis=0.5
POST /control?wifi=1&ssid=MyWiFi&pass=12345678   // 切到 STA 模式連 MyWiFi，自動重啟
POST /control?wifi=0                             // 回到純 AP 模式，自動重啟
```

### `GET /test` — 手動測試

| 參數 | 範圍 | 說明 |
|------|------|------|
| `en` | 0/1 | TEC EN 腳 |
| `fan` | 0–255 | 風扇 PWM |
| `cool` | 0–255 | 製冷 PWM |
| `heat` | 0–255 | 加熱 PWM |

帶 `fan` 會設 `fanManual`（自動邏輯不再改風扇）；帶 `cool`/`heat` 會設 `tecManual`，此時 `controlTemp()` 整個跳過，**包括所有安全保護**。兩個旗標都要按「停止系統」或重新開啟系統才會清除。

### `GET /strip` — LED 燈帶亮度

`?b=0-100` 設定亮度（GPIO13/D7 → IRLZ44N，PWM 5kHz），回傳 `{"strip":30}`。亮度不存 EEPROM，重啟後為 0。網頁「LED 燈帶」區塊有滑條與 關/30%/全亮 快捷鍵。

### `GET /diag` — 診斷資訊

```json
{
  "pin": 4,
  "pinState": 1,
  "dsOk": true,
  "deviceCount": 3,
  "nest": 29.1,
  "room": 29.3,
  "vent": 29.5,
  "conversionPending": false
}
```

用於硬體偵錯：確認腳位狀態、匯流排裝置數量、感測器讀值。

## 相機系統（ESP32-S3 AI Camera）

### 硬體

- **DFRobot DFR1154**（ESP32-S3，16MB Flash + 8MB OPI PSRAM，OV3660，940 nm IR）
- ⚠️ **必須用 `dfrobot_dfr1154` 板型**——通用 `esp32-s3-devkitc-1` 無 PSRAM，代碼強制 `CAMERA_FB_IN_PSRAM` 會導致 DMA 崩潰、串流卡死
- IR 燈：GPIO47；LED：GPIO3

### 網路

- WiFi STA 模式，優先連手機熱點（`OPhone 12`），10 秒連不上就回退連主 ESP 的 AP（`ESP32-TEMP` / `12345678`）；掉線後 `loop()` 每 5 秒重連
- mDNS：`esp32-cam`（主 ESP 為 `esp32-tec`）

### 雙端口架構（串流與控制分離）

| 路由 | 連接埠 | 用途 |
|------|--------|------|
| `/stream` | 80 | MJPEG 串流（VGA 640×480，jpeg_quality 16） |
| `/capture` | 80 | 單張 JPEG |
| `/light` | 81 | `?ir=1/0` / `?led=1/0` 紅外燈 / LED |
| `/status` | 81 | JSON 狀態 `{"ir":0,"led":0}` |

**IR/LED 由前端直連相機 81 端口控制**（不經主 ESP 代理），避免串流佔住控制端點導致燈光無反應。

### 已修復的坑（全部解決）

1. 板型無 PSRAM → DMA 崩潰（改 `dfrobot_dfr1154`）
2. 幀緩衝洩漏 → 發送失敗未釋放（加 `esp_camera_fb_return(fb)`）
3. 慢客戶端阻塞串流 5 秒 → `send_wait_timeout = 1s`
4. 客戶端斷開後 `while(true)` 卡死 → 探針偵測斷開退出

### 建置

相機是獨立的 PlatformIO 專案，**必須先進 `camera/` 目錄**（在倉庫根目錄執行會報 `UnknownEnvNamesError`）：

```bash
cd camera
pio run -e esp32s3cam
pio run -e esp32s3cam --target upload
```

## CSV 資料匯出

### 格式

現行格式（BME 接入後，12 欄；以下為格式示意，非真實數據）：

```csv
# TEC 蟄眠實驗
# 導出時間: 2026/9/20 下午4:07:30
時間,巢穴,活動區,出風口,風扇(%),狀態,BME溫度,BME濕度,BME氣壓(hPa),BME氣體(kΩ),氣體相對(%),露點
2026/9/20 下午4:07:30,29.12,29.34,29.41,0,維持,28.9,62.3,1009.4,35.2,100,20.9
2026/9/20 下午4:07:31,29.12,29.34,29.41,100,製冷,28.9,62.3,1009.4,35.2,100,20.9
```

- BOM（U+FEFF）開頭 → Excel 直接開不會亂碼；接著 2 行 `#` metadata，第 3 行才是表頭
- 溫度 2 位小數；BME 欄位在未接感測器時留空
- 時戳含完整日期時間（`toLocaleString()`，格式隨瀏覽器地區設定，可能是 `7/22` 或 `上午/下午`）
- 每行是一次網頁輪詢（約 1 秒），但溫度約 4 秒才更新一次，中間是重複值
- 檔案名含時間：`TEC_2026-07-22_16-07-30.csv`
- `P1`–`P3` 資料夾裡的舊 CSV 只有前 6 欄（早於 BME 接入）；7/22 的 A 組檔案沒有 metadata 行

### 數據範圍

兩個記憶體緩衝區：

| 緩衝區 | 上限 | 用途 |
|--------|------|------|
| `H` | 600 筆 | 圖表顯示（滑動窗口，只保留最近約 10 分鐘——實測 ≈1 秒/筆，串流時 5 秒/筆） |
| `allData` | 10000 筆 | CSV 匯出（超過上限時最舊資料被丟棄） |

**注意：** 關掉瀏覽器分頁或 ESP32 重啟 → `allData` 全部遺失。這是已知缺陷（LIMITATIONS.md #5）。
